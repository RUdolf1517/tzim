# Audit of 0.11.0 — code, contract and evidence

**Status: closed.** This is a frozen record, not a living document. The findings are tracked as issues
(`#26`–`#47`); when an issue is fixed, this file is not edited — the fix and its `CHANGELOG` entry become the
record. Nothing here ships in the crate (`Cargo.toml` excludes this directory on purpose).

**Audited commits.** The audit started on `97fa0cd` (v0.10.0), then moved with `main`: `b6af0e9` (v0.11.0) and
`29d00c7` (v0.11.0 + winget packaging). Every finding below was re-verified against `29d00c7`, and every
`file:line` reference points at that tree. Between `b6af0e9` and `29d00c7` nothing under `src/`,
`docs/guarantees.md`, `docs/safety.md`, `docs/cli.md` or `docs/testing.md` changed, so the references did not
shift; `README.md` moved by one line and the references there were re-derived.

**Version still affected: 0.11.0, as published.** The release is live and `install.sh` distributes the binary
that contains B1.

## 0. How to read this document

| Label | Meaning | What fixes it |
| --- | --- | --- |
| **B\*** | Behaviour contradicts the contract, or the program tells the user something untrue | code + test |
| **V\*** | The evidence for a promise is missing or weaker than the promise | test (or a narrower promise) |
| **D\*** | A document describes code that is not there, or describes something that does not exist | document (sometimes code) |
| **G\*** | Claimed as verified, but no verification exists | test/CI or drop the claim |
| **T\*** | A task with a priority and a definition of done (§7) | — |
| **O\*** | An open question that needs the owner's decision (§8) | — |

Priorities: **P0** — distorts trust or breaks a run; **P1** — a promise is unsupported or a document is
wrong; **P2** — debt that does not change any promise.

**Method, and its limits.** Everything here comes from reading the code and the documents, plus four
mechanical checks: a `python3` internal link/anchor checker over every Markdown file; a cross-check of all 30
long CLI flags against `--help`, `man/tzim.1` and the three completion files; and **independent numeric
re-implementations in Python** of two algorithms that cannot be verified by reading (Adler-32 and the JPEG
Huffman table generator, §4.1–§4.2).

`cargo` and `rustc` do not exist in the environment this audit was performed in; `crates.io`,
`static.rust-lang.org` and `release-assets.githubusercontent.com` were unreachable, so **no build, no test, no
size measurement and no run of the published binary happened**. Every statement about behaviour is derived
from code. Anything that needs execution is marked *"requires verification"*. A Python port of an algorithm
proves a property of *that algorithm*, not of the compiled code: if the port misreads the Rust, the conclusion
is wrong. Saying so is cheaper than a false green.

## 1. The project's philosophy in one screen (calibration for every decision below)

1. **The contract is normative, the code is secondary.** `docs/guarantees.md:3-4`: "if the code and this
   document disagree, that is a bug". So a divergence is fixed in the code when the document is right in
   substance, and in the document when the promise was stronger than reality (owner decisions 1 and 4).
2. **A refusal beats a guess.** Anything not understood is `skipped` with a reason; a file is never "repaired".
3. **Verification is not done with the writer's code.** The V1/V2/V3 levels are named honestly, including the
   weakness of JPEG.
4. **Strictly smaller or nothing** — with exactly one exception, `--strip-metadata` (invariant I2).
5. **Every promise has a test with a name** (`T-*`), and a format reaches the README only after its contract
   exists.
6. **The binary size is a requirement, not a side effect.** The size is measured in CI, each format family is
   behind a feature, and the owner's decision 9 sharpens this: the goal is to *reduce* it by removing junk.

Acceptance criterion for any change: either the output bytes do not change, or the change is backed by a
clause of the contract and a test; documentation and code must agree **in the same commit**.

## 3. Findings

### P0 — distorts trust or breaks a run

#### B1. `--strip-metadata` with an equal-size candidate is reported as an internal error (exit 1)

This is the only **false-failure bug** found, and it breaks I2, the README and the exit-code contract at once.

| Side | Fact |
| --- | --- |
| Contract | `docs/guarantees.md:141` (I2): equality is allowed under `--strip-metadata`, "A larger candidate is never accepted". `docs/cli.md:129-131`: "never larger rather than strictly smaller" |
| gzip | `src/formats/gzip.rs:199-207`: `worth_writing` includes `total == data.len() && header != original_header` → `Cand::Written(total)` |
| ZIP | `src/formats/zip.rs:630`: `Some(out) if out.len() < data.len() \|\| (opts.strip_metadata && out.len() == data.len())` → `Cand::Written(len)` |
| Pipeline | `src/pipeline.rs:198-202`: `if written == 0 \|\| written >= snapshot.len { Err(Error::internal("a candidate was accepted that is not strictly smaller")) }` → `Status::Failed`, exit **1** |
| README | `README.md:23` and `README.md:130`: "only if the new one is strictly smaller", "Equal or larger candidate: discarded" — also wrong under the flag |

**Deterministic reproduction (ZIP, independent of recompression quality).** An archive with a `stored` entry
(`ZipEntrySpec::stored`, method 0 — the payload is never recompressed), an empty archive comment, and non-zero
DOS timestamps (the `build_zip` fixture always writes `time=0x6000`, `date=0x5a21`). `rebuild` then returns a
file of **exactly the same size**, `changed == true` because of the timestamps, and the pipeline falls into
`internal`. Expected: `optimized`, exit 0.

```bash
# requires verification on a built binary
tzim stored.zip --strip-metadata ; echo $?   # today: 1 + "internal error"; expected: 0
```

**gzip analogue:** a header with a non-zero MTIME and no FNAME/FEXTRA/FCOMMENT/FHCRC, body already at level 9.
The test must tolerate the body shrinking: assert **exit 0 and no `internal`**, and, when the result is
`optimized`, that MTIME is zeroed.

**Fix (two places).**

1. `src/pipeline.rs:198` — replace the hard `written >= snapshot.len` with the rule from I2:

```rust
let acceptable = if cfg.strip_metadata {
    written <= snapshot.len          // "never larger"
} else {
    written < snapshot.len           // "strictly smaller"
};
if written == 0 || !acceptable {
    return Err(Error::internal(
        "a candidate was accepted that is larger than the original",
    ));
}
```

2. `src/formats/mod.rs` (`verify`) — make the promise of G3 clause 4 (`docs/guarantees.md:62`) literally true
   instead of implied (see D3). One size predicate at the dispatcher's entry:

```rust
fn size_ok(original: usize, candidate: usize, strip: bool) -> bool {
    candidate < original || (strip && candidate == original)
}
// in verify(): if !size_ok(..) { return Err(Error::verify("candidate is larger than the input")) }
```

   A separate function is needed so that it can be unit-tested without building real files. Nested children
   (`--nested`) are unaffected: `zip.rs:830` requires a strictly smaller child.

   Note: after this change equality is allowed for *any* handler under the flag. Today only ZIP and gzip can
   produce it, and both guarantee that the content changed (`changed` in `rebuild`; `header !=
   original_header` in `optimize`). For a hard guarantee, compare `candidate != input` before accepting; the
   price is a `memcmp` over the whole file, so pinning the invariant with handler tests (`strip_metadata_*`,
   which already exist) is cheaper.

**Tests (per `CONTRIBUTING.md` §3, a regression must fail before the fix):**

| Test | Where | Assertion |
| --- | --- | --- |
| `strip_metadata_equal_size_zip_is_optimized` | `tests/integration.rs` | `stored` archive, `--strip-metadata`: exit 0, status `optimized`, size unchanged, `time`/`date` zeroed in local and central headers, file mtime preserved |
| `strip_metadata_equal_size_gzip_is_not_a_failure` | `tests/integration.rs` | exit 0, no `internal`, MTIME = 0 |
| `verification_rejects_a_larger_candidate` / `…_accepts_an_equal_one_only_when_stripping` | `src/formats/mod.rs` unit | the size predicate |

**Documents in the same commit:** `README.md:23`, `README.md:130`, `docs/cli.md:129-131` — add the qualifier
"unless `--strip-metadata`, which never grows a file"; `docs/guarantees.md:141` — remove the duplicated
insertion "(`--strip-metadata`, §2.7)"; a "Fixed" section in `CHANGELOG.md`.

### P1 — trust: verification is almost untested

#### V1. The second line of defence (`verify`) has no deterministic test for 6 of 7 formats

The project calls `verify` the second line of defence: the handler writes a candidate, which is then decoded
independently and compared with the original (`src/pipeline.rs:205`, `src/formats/zip.rs:832` for nested
entries). It is the last barrier between a codec bug and a corrupted file on disk. **No test proves that this
barrier can refuse anything.**

Measured on `29d00c7`:

| What was searched | Result |
| --- | --- |
| `verify` in `tests/integration.rs` (89 tests) | **0 mentions** |
| `is_err()` in `tests/integration.rs` | **0** |
| Calls to `verify`/`verify_icon` **from test code** | **3, all in one file**: `src/formats/zlib.rs:302` (round trip) and two negative ones at `zlib.rs:151,164` |
| Negative asserts in the other handlers' unit tests | `gzip` 5, `jpeg` 4, `png` 3, `zip` 2, `tiff` 1 — **every single one targets a parser**: `parse_header`, `inspect`, `validate_table`, `parse`, `numbers`, `parse_archive`, `find_eocd` |

So `png::verify`, `jpeg::verify`, `tiff::verify`, `zip::verify`, `gzip::verify` and `png::verify_icon`
(ICO/CUR) **are not called by any test**. The distinguishing rules they encode are unpinned:

- PNG: byte equality of every non-IDAT chunk, matching `fcTL`/`fdAT` sequence numbers, APNG frame comparison
  (`compare_images`/`compare_frames` in `png.rs`);
- JPEG: markers outside the Huffman tables unchanged, unused tables preserved, DCT coefficients equal
  (`jpeg.rs:1428-1478`);
- TIFF: every tag value preserved, the permitted `Compression` transition (1|8 → 8), strip-by-strip comparison
  of the decompressed data (`tiff.rs:857+`);
- ZIP: masking of the fields a rewrite *may* change, and re-verification of a nested child (`zip.rs:889-1019`);
- gzip: the header compared against the strict result of `--strip-metadata` (`gzip.rs:220-227`).

**Why it matters here.** `verify` is the only place where a codec bug becomes a corrupted file if it is not
caught. Inverting a single comparison in any of those blocks breaks no test: the unit tests check what the
handler *writes*, and the integration tests check that the result is *smaller and decodable by the same crate*.
A verifier that is too permissive is unobservable.

The only thing that ever runs `verify` on arbitrary data is fuzzing (`src/fuzz_api.rs:46,70`,
`.github/workflows/fuzz.yml`). That is **a tripwire, not a proof**: 60 seconds per target per PR (by its own
comment, `fuzz.yml:7-10`), non-deterministic, and — as V2 shows — the input class from B1 never reaches it.

**Fix (tests, no behaviour change):**

| Test | Format | What is corrupted in a valid candidate | Expected |
| --- | --- | --- | --- |
| `verification_rejects_changed_pixels` | PNG | one byte inside IDAT after recompression | `decoded pixels differ` |
| `verification_rejects_a_dropped_chunk` | PNG | remove `tEXt` by hand (no flag) | chunk count / not preserved |
| `verification_rejects_a_changed_frame_sequence` | APNG | `fdAT` sequence +1 | `fdAT sequence number changed` |
| `verification_rejects_a_changed_table` | JPEG | replace one unused DHT table | marker/table error |
| `verification_rejects_changed_coefficients` | JPEG | substitute one symbol in the entropy stream | coefficient/decode error |
| `verification_rejects_a_changed_tag_value` | TIFF | change `ImageWidth` in the candidate | tag value error |
| `verification_rejects_a_changed_stored_entry` | ZIP | one byte in a `stored` entry | CRC error |
| `verification_rejects_a_surviving_comment` | ZIP | put the archive comment back under the flag | `comment survived` |
| `verification_rejects_a_kept_filename` | gzip | keep `FNAME` under the flag | stripped-header error |
| `verification_rejects_a_corrupted_icon_payload` | ICO | one byte inside the embedded PNG | error |
| `verification_rejects_a_larger_candidate` | all | candidate longer than the input | size error (see D3) |

**How to prove these tests are not decoration (this is the acceptance criterion).** For each test, apply a
mutation to `verify` that it must catch; a test that survives its own mutation is deleted:

| Mutation in `verify` | The test that must fail |
| --- | --- |
| `buf_a != buf_b` → `false` | `verification_rejects_changed_pixels` |
| `kept_a.len() != kept_b.len()` → `false` | `verification_rejects_a_dropped_chunk` |
| `x.data[..4] != y.data[..4]` → `false` | `verification_rejects_a_changed_frame_sequence` |
| `marker_sequence(..) != marker_sequence(..)` → `false` | `verification_rejects_a_changed_table` |
| `decoded_before.planes != decoded_after.planes` → `false` | `verification_rejects_changed_coefficients` |
| `a.value != b.value` → `false` | `verification_rejects_a_changed_tag_value` |
| compare without CRC in `mask_local(.., checksum)` | `verification_rejects_a_changed_stored_entry` |
| `b[..info_b.header_len] != stripped_header(a)` → `false` | `verification_rejects_a_kept_filename` |

The model to copy already exists: `src/formats/zlib.rs:151,164` calls `verify` with a tampered header and a
tampered payload. The same is needed for the other six.

#### V2. Three different size thresholds — and fuzzing is blind to B1 exactly because of it

One predicate, "may this candidate replace the original?", is written three ways:

| Place | Code | Meaning |
| --- | --- | --- |
| `src/fuzz_api.rs:43` (`roundtrip`) | `candidate.len() >= data.len()` → `false` | equality rejected |
| `src/fuzz_api.rs:67` (`roundtrip_strip`) | `candidate.len() > data.len()` → `false` | **equality accepted and passed to `verify`** |
| `src/pipeline.rs:198` | `written >= snapshot.len` → `internal error` | equality is an **error** |
| `src/formats/zip.rs:630`, `src/formats/gzip.rs:199-207` | equality allowed under `--strip-metadata` | equality is legitimate (I2) |

Consequences for accepting B1:

1. The threshold in `roundtrip_strip` agrees with the handlers and with I2, so `>=` in the pipeline is an
   **internal inconsistency**, not a debatable reading of the contract. B1 is confirmed a second time, by code
   written independently of the pipeline.
2. Fuzzing cannot find B1 **by construction**: `roundtrip` (`:43`) drops an equal-size candidate before
   `verify`; `roundtrip_strip` (`:67`) passes it to `verify`, which accepts it (the candidate is correct), and
   the target returns `true`. The exact input on which the binary exits 1 with `internal error` looks like a
   success to the fuzzer.
3. After T8 all four sites must read the same way. One predicate, one function called from everywhere
   (`size_ok(original, candidate, strip)`); three copies of a condition will diverge again.

**Test:** a unit test on the predicate (all four combinations) plus the B1 integration test (T8). Separately,
an assertion in `fuzz_api.rs` that both targets use the shared predicate, otherwise the divergence returns
silently.

### P1 — documents describe code that is not there

#### D1. `docs/safety.md` §1, steps 2 and 5: "a snapshot from the open handle" and "detect from the open handle"

| Document | Code |
| --- | --- |
| `docs/safety.md:18`: "Open read-only and capture a snapshot **from the open handle**" | `src/pipeline.rs:80`: `fs::symlink_metadata(path)` — the snapshot comes from `lstat`; no handle is opened |
| `docs/safety.md:24`: "Detect the format … **from the already-open handle, not by re-opening the path**" | `src/pipeline.rs:112`: `detect::detect_path(path)` re-opens the file (`src/detect.rs:118`); then `src/pipeline.rs:184`: `fs::read(path)` — a third open |

Per owner decision 4 the **document** is corrected (the code will not be hardened to a single handle).
Suggested wording for step 2:

> **2. Stat without following links** (`lstat`) and take the snapshot from it: length, modification time, access
> time, permission bits, hard-link count, `(device, inode)`.

and for step 5:

> **5. Detect the format** by opening the path read-only and reading its first bytes; the file is then read in
> full, once, by the handler.

Plus one honest sentence in §6: the race between the re-open and the `rename` is not closed by an advisory lock;
it is caught by the re-check of `(dev, ino, len, mtime)` before replacement (`src/replace.rs:139-158`), which is
the best available mechanism.

#### D2. `docs/guarantees.md:40`: "G1 is verified by a content hash before and after"

Neither `pipeline.rs` nor `replace.rs` computes any content hash. G1 actually holds because nothing is written on
those paths, and the only candidate is removed by the guard (`src/replace.rs:71-77`).

**Fix:** replace the sentence with: "G1 holds because nothing is written on these paths; the candidate guard
removes the temporary file on every exit. The only comparison the program makes is the re-check of `(device,
inode, length, mtime)` before replacement." Hashing in tests (`docs/testing.md:16`) stays a property of the
tests, not of the program.

#### D3. `docs/guarantees.md:56-63`: the size is claimed to be checked by verification

Clause 4, "G3 always verified by … confirming the candidate is not larger", is not implemented in any `verify()`:
there is no length comparison in `src/formats/{png,gzip,zip,tiff,jpeg,zlib}.rs`. The rule lives in the handlers
(`png.rs:570`, `tiff.rs:786`, `jpeg.rs:1421`, `zip.rs:630`, `gzip.rs:201`, `zlib.rs:203`, `png.rs:999`) and in
`pipeline.rs:198`.

**Fix:** either implement the predicate in `verify` (recommended — see B1, item 2), or rewrite clause 4 as "the
pipeline accepts a candidate only if …" with a link to I2. Doing both creates two sources of truth; choose one —
`verify` plus a reference from §2 is recommended.

#### D4. `docs/safety.md:50-51`: the temporary file name and "removed on success"

| Document | Code |
| --- | --- |
| `.tzim-<pid>-<random>.tmp` | `src/replace.rs:28`: `.tzim-{pid}-{nanos}-{attempt}.tmp` (no randomness) |
| "removed by an RAII guard on success, error and early return" | on success the file is not removed but **renamed**, and only then is the guard disarmed (`src/replace.rs:173-174`) |

**Fix:** use the actual name and say plainly: "on failure, an early return and dropping the guard deletes the
temporary file; on success the guard is disarmed after the rename, so the candidate becomes the destination".

#### D5. `docs/safety.md:164-166`: "prints a warning when euid == root"

The code (`src/pipeline.rs:152-167`) prints nothing: it compares the `uid` of the original's owner with the `uid`
of the temporary file (that is, ours), and on mismatch **skips** the file with a `note` unless
`--allow-root-ownership-change` is given. The condition is not about root: as an ordinary user, a file owned by
someone else is also skipped. The check exists on Unix only.

**Fix:** rewrite the paragraph: "A file whose owner differs from the user running Tzim is skipped with a reason,
unless `--allow-root-ownership-change` is given; the check is Unix-only, because ownership is not comparable on
other platforms." Drop "prints a warning".

#### D6. `docs/cli.md`: three wrong examples and lists

| Line | What is wrong | What is correct |
| --- | --- | --- |

## 4. Checked, and found sound

Items 4.1–4.3 are not reading but **independent checks**: the algorithm was lifted out of Rust into Python and
checked against an external reference or by brute force. Without `cargo` this is the only way to make a claim
that is worth more than "it looked right".

### 4.1. Adler-32 (`src/formats/zlib.rs:129-160`) — correct

This is exactly the danger the project names in `docs/testing.md`: "not the same defective algorithm for writing
and for checking". zlib is the only format that computes its checksum **by hand** (gzip and ZIP use `crc32fast`),
and an error would be invisible: `verify` compares the trailer against a value produced by the same function.

The `update`/`finish` port was compared with the reference `zlib.adler32`:

| Input | tzim port | `zlib.adler32` |
| --- | --- | --- |
| `b"Wikipedia"` | `0x11e60398` | `0x11e60398` |
| empty | `0x1` | `0x1` |
| 10 000 zeros | `0x27100001` | `0x27100001` |
| 1 MiB of `0xff` | `0x8e88ef11` | `0x8e88ef11` |

Plus 44 further comparisons at lengths chosen around the `NMAX = 5552` boundary (0, 1, 2, 5551, 5552, 5553,
11103, 11104, 11105, 20000, 100000) and four content patterns (random, zeros, `0xff`, a constant) — **0
mismatches**, 48 comparisons in total. The block boundary is handled correctly and the `u32` sums cannot
overflow (the `NMAX` bound is chosen as in zlib).

### 4.2. The JPEG Huffman table generator (`src/formats/jpeg.rs:474-662`) — legal on the whole search

This is the most dangerous code in the project after the entropy codec: if a generated table is illegal
(overfull by Kraft, contains the forbidden all-ones code, repeats a symbol), the stream it writes cannot be read
by any decoder — at best a `failed` file, at worst a corrupted one if `verify` uses the same `HuffDec`.

`optimal`/`flat_table`/`validate_table` were ported to Python and brute-forced:

| Check | Result |
| --- | --- |
| 20 000 random distributions (symbol counts 1…256, weights from `randint(1,1)` to `randint(1,10⁹)`, Pareto tail) | **all 20 000 took the optimal branch, 0 illegal tables** |
| adversarial Fibonacci weights over 2, 4, 8, 16, 32, 64, 128, 256 symbols (exactly where `flat_table` would produce a complete tree with the all-ones code) | no illegal table; `kraft` = 0.75…1.0, the all-ones rule never violated |
| reachability of the `flat_table` fallback | not reached on any input — the "safety" branch is dead, but harmless |

The comment "The table stays legal and effectively optimal to within a single bit" is accurate:
`validate_table` is called in both `Enc::build` and `HuffDec::build`, so an illegal table cannot reach the writer
silently.

### 4.3. Panics: four calls in the whole of `src/`, all safe

Release builds use `panic = "abort"` (`Cargo.toml:61`), so **any** panic kills the entire run rather than one file —
under `-r` over a tree that means refusing to process the rest. An audit of every `src/**/*.rs` outside
`#[cfg(test)]`:

| Place | Call | Safe? |
| --- | --- | --- |
| `src/formats/png.rs:183` | `.position(IDAT).unwrap()` | yes: immediately above (`:174-176`) is `if idat.is_empty() { return Err(..) }` |
| `src/formats/png.rs:184` | `.rposition(IDAT).unwrap()` | yes, same guard |
| `src/progress.rs:99` | `.expect(..)` on a template | yes: the templates are constants and a test parses them |
| `src/replace.rs:62` | `.expect("temporary file handle …")` | yes: a type invariant, `committed` is only set after `file.take()` |

There are no other `unwrap`/`expect`/`panic!`/`unreachable!`/`todo!` in production code. This is a strength of
the project, and it is worth pinning so that the next `.unwrap()` cannot appear silently: `[lints.clippy]
unwrap_used = "deny"` in `Cargo.toml` (which today has only `[lints.rust] unsafe_code = "forbid"`,
`Cargo.toml:79-80`) together with a `clippy.toml` containing `allow-unwrap-in-tests = true` — otherwise the lint
would break the 101 unit tests where `unwrap` is appropriate. The two `unwrap`s in `png.rs` are still better
replaced with `?`: the compiler does not care, the next reader does.

### 4.4. Where verification is genuinely independent, and where it is not

The central question for any lossless optimizer is *what* checks the result. This is a map of the boundaries of
trust, not a verdict; it deserves a paragraph in `guarantees.md` §3 one day (see D15).

| Format | Written by | Checked by | Independent? |
| --- | --- | --- | --- |
| PNG | own filter + `flate2` + own chunks | the `png` crate (a full decoder, `png.rs:715-900`) | **yes**: a different codec on the reading side, plus byte comparison of every non-IDAT chunk |
| ICO/CUR | the same embedded PNGs | `verify_icon` → the same `png` decoder plus byte comparison of directory records | **yes** |
| gzip | `flate2` + own header | a `flate2` decoder, byte comparison **plus** CRC32/ISIZE taken from the original file (`gzip.rs:44-55`) | partly: the codec is shared, but the CRC is an **external** anchor written by someone else's archiver before us |
| zlib | `flate2` + own 2-byte header | a `flate2` decoder + Adler-32 from the original (`zlib.rs:215-247`) | partly, with an external anchor (§4.1) |
| ZIP | `flate2` on write | each entry's CRC is checked against the **stored** value before any work (`zip.rs:610-618`, `:790-800`), then both sides are inflated and compared | partly: the codec is shared, but the original side is pinned by a CRC from another archiver |
| TIFF | `flate2` (input `none`/`deflate` → output always `deflate`, `tiff.rs:444`) | for strips that were **not** compressed the original is raw bytes and no decoder is needed (**fully independent**); for already-compressed strips both sides go through `flate2` | partly: **TIFF has no external anchor**, unlike gzip/ZIP/zlib. This is the only format where a symmetric `flate2` bug would be theoretically invisible. The practical risk is low (strip sizes are compared, `flate2` is a third-party, well-tested crate), but it should be stated rather than left implicit |
| JPEG | own encoder | own decoder (shared codec) | **no** — and this is already stated honestly in `guarantees.md` §2.6 (V3); T14/`#39` addresses it in a separate release |

Conclusion for acceptance: PNG and ICO rows are a real second line of defence; gzip/zlib/ZIP are "decoder plus an
external checksum", which is sufficient; TIFF is sufficient but not absolute; JPEG is a known limitation. None of
this is a found defect. It is a map, so that the promise "every candidate is checked by an independent decoder"
(`README.md:22`) is not read more broadly than it is.

### 4.5. Read-through checklist (things that were looked for and are correct)

- Content-based detection does not conflict between formats: the first bytes of PNG/gzip/ICO/JPEG/TIFF/ZIP do not
  satisfy the zlib condition, and zlib is checked last (`src/detect.rs:51`).
- ZIP stripping is correct on offsets: local `time+date` = 10..14, central `time+date` = 12..16, comment length
  = 32..34, EOCD comment length = 20..22 (`src/formats/zip.rs:730-782`), and the `mask_*` helpers in verification
  mirror this.
- gzip stripping keeps `CM`, `XFL`, `OS` and zeroes only MTIME plus the flag bits (`src/formats/gzip.rs:174-176`).
- PNG/TIFF/JPEG/ICO/zlib never return an equal-size candidate: `png.rs:570`, `tiff.rs:786`, `jpeg.rs:1421`,
  `png.rs:999`, `zlib.rs:203` — which is why B1 is reachable only through ZIP and gzip.
- The order "temp file → write → verify → rename → disarm" really leaves no point where the original is
  partially written (`src/pipeline.rs:150-215`, `src/replace.rs:163-181`).
- `unsafe` is genuinely banned: `#![forbid(unsafe_code)]` in `lib.rs`/`main.rs` and `[lints.rust]` in `Cargo.toml`;
  there is no `unsafe` in the code.
- The size gate in CI exists and matches the document: `budget=1207296` (1179 KiB) at
  `.github/workflows/ci.yml:278`, with the feature matrix next to it.
- Nested ZIP entries are verified **twice**: first `nested_child` (`src/formats/zip.rs:832`) drops a child that
  fails its own `verify`, then `verify_nested_change` (`zip.rs:986-1019`) repeats the check inside the parent's
  contract. A nested failure cannot fail the parent: `is_err()` → "keep the original bytes" (`zip.rs:826,832`).
- gzip/zlib headers and trailers are copied from the original rather than recomputed (`gzip.rs:174-176`;
  `zlib.rs:207-211`), so a broken `crc32fast`/`Adler32` cannot silently corrupt the output — it would only cause
  a refusal. `gzip::inspect` also checks the **stored** CRC and ISIZE against the inflated data (`gzip.rs:44-55`),
  so a corrupt input is refused rather than "healed".
- Replacement: `changed_since` compares `(len, mtime, dev, ino)` before `rename` (`src/replace.rs:139-158`), and
  `rename` is the only operation that changes the visible state (`replace.rs:166-181`); attributes and times are
  applied to the temporary file **before** the rename. Hard links are handled explicitly: `snapshot.nlink > 1` →
  `skipped` without `--allow-hardlinks` (`src/pipeline.rs:103`).

- **O4.** Where audits live — **resolved**: this directory (see `docs/audits/README.md`).
- **O5.** Are `T-*` rows wanted for the new tests in `docs/testing.md` §2 (for example `T-STRIP-11`,

### 9.3. The Huffman table generator

The port below is a line-by-line translation of `optimal`, `flat_table` and `validate_table`
(`src/formats/jpeg.rs:474-662`). It was used to produce §4.2. **Re-check it against the Rust whenever the
generator changes:** the port catches an error in the *algorithm*, not in the translation.

```python
import random

def flat_table(counts):
    vals = [s for s in range(256) if counts[s] > 0]
    n = max(len(vals), 1)
    length = 1
    while (1 << length) <= n:
        length += 1
    out = [0] * 17
    remaining = n
    level = length
    while remaining > 0 and level <= 16:
        take = min(remaining, 255)
        out[level] = take
        remaining -= take
        level += 1
    return out, vals


def validate(counts, vals):
    if counts[0] != 0:
        return "zero-length code"
    total = sum(counts[1:])
    if total == 0 or total > 256 or total != len(vals):
        return "symbol count inconsistent"
    kraft = sum(counts[l] << (16 - l) for l in range(1, 17))
    if kraft > (1 << 16):
        return "overfull"
    if len(set(vals)) != len(vals):
        return "repeated symbol"
    code = 0
    for l in range(1, 17):
        c = counts[l]
        if c > 0 and code + c - 1 == (1 << l) - 1:
            return "all-ones code"
        code = (code + c) << 1
    return None


def optimal(counts):
    """Returns (counts, vals, source) mirroring the Rust implementation."""
    if all(c == 0 for c in counts):
        c, v = flat_table(counts)
        return c, v, "flat(empty)"
    freq = list(counts) + [1]
    codesize = [0 if f > 0 else -1 for f in freq]
    others = [-1] * 257
    while True:
        c1 = -1
        best = None
        for i in range(257):
            if freq[i] > 0 and (best is None or freq[i] < best):
                best = freq[i]
                c1 = i
        c2 = -1
        best2 = None
        for i in range(257):
            if i != c1 and freq[i] > 0 and (best2 is None or freq[i] < best2):
                best2 = freq[i]
                c2 = i
        if c2 == -1:
            break
        freq[c1] += freq[c2]
        freq[c2] = 0
        k = c1
        while True:
            codesize[k] += 1
            nxt = others[k]
            if nxt < 0:
                break
            k = nxt
        others[k] = c2
        k = c2
        while True:
            codesize[k] += 1
            nxt = others[k]
            if nxt < 0:
                break
            k = nxt

    bits = [0] * 257
    for size in codesize:
        if size > 0:
            bits[size] += 1
    limited = True
    for i in range(256, 16, -1):
        while bits[i] > 0:
            if bits[i] < 2:
                limited = False
                break
            j = i - 2
            while j > 0 and bits[j] == 0:
                j -= 1
            if j == 0:
                limited = False
                break
            bits[i] -= 2
            bits[i - 1] += 1
            bits[j + 1] += 2
            bits[j] -= 1
        if not limited:
            break
    if not limited:
        c, v = flat_table(counts)
        return c, v, "flat(limit)"

    symbols = sorted(
        [(counts[s], s) for s in range(256) if counts[s] > 0],
        key=lambda t: (-t[0], t[1]),
    )
    lengths = []
    for ln in range(1, 257):
        lengths.extend([ln] * bits[ln])
    while len(lengths) > len(symbols):
        lengths.pop()
    if len(lengths) != len(symbols):
        c, v = flat_table(counts)
        return c, v, "flat(lengths)"
    vals = [s for _, s in symbols]
    for _ in range(4):
        out = [0] * 17
        ok = True
        for ln in lengths:
            if ln == 0 or ln > 16:
                ok = False
                break
            out[ln] += 1
        if not ok:
            c, v = flat_table(counts)
            return c, v, "flat(range)"
        err = validate(out, vals)
        if err is None:
            return out, vals, "optimal"
        if lengths and lengths[-1] < 16:
            lengths[-1] += 1
        else:
            break
    c, v = flat_table(counts)
    return c, v, "flat(attempts)"

# --- checking harness -------------------------------------------------------
if __name__ == "__main__":
    def check(counts):
        c, v, src = optimal(counts)
        return validate(c, v), src

    random.seed(1234)
    paths, illegal = {}, 0
    for _ in range(20_000):
        n = random.choice([1, 1, 2, 3, 4, 5, 8, 16, 32, 64, 127, 128, 129, 200, 255, 256])
        counts = [0] * 256
        for s in random.sample(range(256), n):
            scale = random.choice([1, 10, 100, 10 ** 4, 10 ** 9])
            counts[s] = max(1, int(random.paretovariate(1.3) * scale) if random.random() < 0.3
                            else random.randint(1, scale))
        err, src = check(counts)
        paths[src] = paths.get(src, 0) + 1
        illegal += err is not None
    print("random distributions: 20000; paths:", paths)
    print("illegal:", illegal)

    for n in (2, 4, 8, 16, 32, 64, 128, 256):   # Fibonacci: flat_table would be complete
        counts, f = [0] * 256, [1, 1]
        while len(f) < n:
            f.append(f[-1] + f[-2])
        for i, w in enumerate(f[:n][::-1]):
            counts[i] = w
        err, src = check(counts)
        print(f"  fib n={n:<4} path={src:<10} illegal={err}")
```
